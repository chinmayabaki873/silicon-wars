# SILICON WARS — Inside the Machine

An interactive, editorial-grade website that explains CPU/GPU architecture through a
restaurant-kitchen metaphor, backed by a deterministic instruction-level simulator.

```
npm install
npm run dev        # http://localhost:5173
npm run build      # production bundle in dist/
npm run preview    # serve the production build on :4173
```

---

## 0. The reference rig

```
CPU   AMD Ryzen 9 8940HX   Zen 4 · 16C/32T · 2.4–5.3 GHz · 32 KB L1d/core
                           16 MB L2 · 64 MB L3 · AVX-512 · DDR5-5200 83.2 GB/s
GPU   NVIDIA RTX 5060 Laptop 8 GB   Blackwell GB206 · 26 SM · 3,328 CUDA cores
                           1.455 GHz · 8 GB GDDR7 128-bit 384 GB/s · 9.7 TFLOPS FP32
                           104 tensor cores · 26 RT cores · 228 KB shared/SM
LINK  PCIe 5.0 ×8 · 32 GB/s theoretical · ~1.6 µs latency
```

The site does **not** query your browser for any of this. It runs the same deterministic
model on every visitor's machine, so the traces are identical locally and when hosted.

## 1. What is on the site

| `#explore` | **01 Kitchen metaphor** | 12-station hover rail (CPU, cores, GPU, workers, instructions, registers, cache, DRAM, VRAM, ALU, scheduler, pipeline). | `#experiments` | **02 Experiment library** | Twenty missions as editorial list rows (not cards): number, thumbnail plate, title, subtitle, difficulty / duration / topology pills, hover-revealed objectives, LAUNCH action, category filter. |
| `#rig` | **03 Reference rig** | The exact hardware every model is calibrated to: Ryzen 9 8940HX + RTX 5060 Laptop 8 GB, with derived constants (4.6× bandwidth ratio, 104× lane ratio). |
| `#architecture` | **04 Architecture atlas** | Clickable SoC block diagram (CPU die + GPU die + shared DRAM/PCIe), per-block detail card, and a log-scale "distance from a chef's knife" latency ladder. |
| `#learn` | **05 Learning experience** | Live excerpt of one execution step rendered in both Beginner and Engineering language, plus the rules that separate the two. |

Every experiment is addressable directly, e.g. `/#/lab/warps-simd-simt`.

## 2. The simulator workspace

Three synchronised panes, one trace:

1. **Kitchen simulation** — the workload as food: chefs/brigades, stations, shelves,
   pantry, warehouse; plus an experiment-specific visual (vector trays, GEMM tile,
   pipeline hazard grid, warp lane masks, convolution pixels, CPU-vs-GPU race,
   PCIe transfer bus).
2. **Architecture diagram** — the same step on silicon. Active blocks pulse, live
   links animate a packet, and it crops to `CPU ONLY` / `GPU ONLY` / `HETEROGENEOUS`.
   Clicking a chef highlights the hardware block and vice-versa (`LOCATE`).
3. **Inspector / Telemetry** — step, cycle, phase badge, component (both languages),
   instruction, inputs, operation, outputs, memory tier + latency, plain-language and
   engineering explanation, next-step preview; or the analytics panel with per-core and
   per-brigade utilisation meters, instruction/cache/memory counters, stage-cycle mix
   and the bottleneck reading.

Transport: play/pause, step back/forward, reset, speed (0.5×/1×/2×/4×), clickable trace
log (jump to any step), keyboard shortcuts (`Space`, `←`, `→`, `R`, `Esc`).

## 3. Why the simulation is honest

* All twenty experiments are generated by pure functions in `src/sim/` from the chosen
  workload parameter. No `Math.random()`, no time-based decoration: the same inputs
  always produce the same trace.
* The model is calibrated to **one specific machine**: AMD Ryzen 9 8940HX (Zen 4,
  16C/32T, 5.3 GHz) and NVIDIA RTX 5060 Laptop 8 GB GDDR7 (Blackwell, 26 SMs,
  3,328 CUDA cores, 384 GB/s, PCIe 5.0 ×8). Every constant — 4-cycle L1, 14-cycle L2,
  46-cycle L3, 90-cycle DDR5, 480-cycle VRAM, 32-lane warps, 64-byte lines — is
  declared in `src/data/rig.ts` and printed on the landing page.
* Nothing reads the visitor's real hardware. No `navigator.hardwareConcurrency`
  benchmarks, no synthetic scores. The UI labels the data as **MODELLED — NOT MEASURED
  HARDWARE** wherever numbers appear.
* The point of each experiment is the *shape* of the behaviour (why a stall happens, why
  transfer cost dominates, why divergence halves throughput), not a ranking of products.

## 4. Design system

* Palette (only): Ivory `#F8F6F0`, Charcoal `#191815`, Espresso `#29221D`,
  Burgundy `#641E25`, Terracotta `#B65335`, Olive `#85865A`, Brass `#B69A63`,
  Stone `#D9D2C6`, White, Soft Grey `#8B8983`, Pale Sand `#EDE8DE`.
* Type: display serif for editorial headlines, humanist sans for reading, restrained
  mono for instrumentation, tags and all numeric telemetry.
* Hairline 1px rules, drafting-grid backgrounds, sand-paper hatching and square corners
  instead of large rounded cards; no blue/purple gradients, no glassmorphism, no neon.
* Motion explains state (a packet travelling a live datapath edge, a mask going dark)
  and never runs "for texture"; `prefers-reduced-motion` is respected through
  framer-motion defaults on the slower reveals.

## 7. Simulated data & snapshots

The model is deterministic, so the whole data set can be frozen once and shipped.

```
src/data/snapshots.ts     buildSnapshot() · checksums · localStorage · export/import
src/lab/SnapshotPanel.tsx the Data tab panel  (export · import · re-freeze · clear)
src/sections/Rig.tsx      "SIMULATED DATA · FROZEN" strip on the landing page
```

* **What is stored.** For every experiment × every workload variant: the step count
  and a 32-bit FNV-1a checksum over the visible parts of each trace. 20 experiments,
  48 variants, 211 steps → ~4 KB of JSON.
* **Where.** `localStorage["silicon-wars:snapshot:v1"]`. It is written automatically on
  the first visit to a lab, and it never leaves the browser.
* **Why it matters for hosting.** Export the JSON (`DOWNLOAD SNAPSHOT` on the landing
  page, or `EXPORT JSON` in the Data tab) and you have the record of exactly what the
  site displayed. Importing it back verifies every checksum against the current model —
  any drift after a code change shows up as a warning instead of silently changing the
  story.
* **Honesty.** Nothing reads real hardware, nothing is uploaded, and the panel says so:
  `STORED LOCALLY · NOT UPLOADED`, `NO NETWORK CALLS`.
